# E-Ink Studio editor

The Image, Text and Draw modes share a 122 × 250 pixel canvas. Images and bitmap-font text remain editable in a project; the drawing layer is stored at native resolution. The pencil, eraser, brush size and drawing undo controls operate on the drawing layer; the eraser removes drawing marks without erasing underlying text or images. The magnifier enlarges the drawing surface inside a scrollable viewport without changing image geometry or exported pixels. Image and text settings remain available in the adjustment panel. Export PNG or the 4,000-byte frame for use outside the project.

Pages can be created, duplicated, reordered and removed locally. These operations do not change the device until **Send changes**. Image batch import previews the common layout, rotation, threshold and dithering settings before applying them to every selected image. Save the project as JSON to preserve the editable image, text and drawing layers. A frame received from a display is raster data: its original text cannot be recovered as editable text, but new layers can be added.

Receiving pages prompts to save the project, replace local work, or cancel. Synchronization compares collection revisions and frame CRCs; only changed frames are written. Individual mutations are durable independently, not as one atomic batch. A lost acknowledgement may mean an operation committed. Reconnect and send again to reconcile a recorded pending operation by revision, ID and CRC without replacing editable layers; the pending journal is also stored in exported projects. If the device reports a revision conflict, save the local project before receiving the latest pages.

Animations are opened through the same **Open image…** input and the File menu entry; a GIF is routed to the animation panel and never replaces the static image, so the PNG path stays byte-identical. The decoder runs locally and accepts GIF87a and GIF89a with interlace, transparency and disposal methods 0–3 (4–7 are rejected as malformed). Every frame goes through the same `renderGray` plus `packBits` calls a still image uses, with the live control values, so fit/cover/fill/tiles, rotation, zoom and position, threshold, brightness, contrast, dithering and inversion apply per frame. Text and drawing layers are not composited into animation frames; they remain part of the static editor only.

The preview plays at the file's own delays with a 100 ms e-ink floor, and it warns rather than silently adjusting when frames ask for zero delay or for less than the floor. The panel reports frame count, encoded bytes, compression ratio and an estimated BLE transfer time; the estimate assumes one acknowledged write plus one 20-byte status read per command at 30 ms, with the negotiated write ceiling or the conservative MTU-23 fallback, and the progress bar shows real time instead. **Keep every Nth frame** and **Minimum delay** fit long GIFs to the device, which accepts at most 64 frames on the wire; the browser-side decoder reads up to 128 so throttling can bring a longer file under that cap. **Use this frame** mirrors one converted frame into the static previews: the source image, text and drawing layers and control values are untouched, and the next render restores the editor's own frame. Preview playback stops when another editing mode is selected, when a static frame is sent, and while a transfer is running; it also pauses while the tab is hidden and resumes when it is visible again.

**Send animation** and **Send and play** upload to the display's animation service and poll status for the durable result; **Verify by reading frames back** is optional and compares each stored frame's CRC with the local frame. **Cancel transfer** sends ABORT while the upload is still staged, so the display keeps its previous animation; once COMMIT has been sent the new animation may already be durable. **Play on display**, **Stop on display** and **Delete from display** act on the device without re-uploading, and the panel polls INFO while connected to show whether an animation is stored and which frame is playing.

The first frame is sent as a full frame and the rest as XOR deltas compressed with PackBits, with an explicit fallback to a full frame when a delta would not be smaller. Playback on the device uses partial refresh bounded by the changed-pixel box, with a clearing full refresh at least every 10 frames or when more than 60% of the panel changes; that behaviour is implemented but has not been optically verified on hardware. No hardware was used for any of this work: the animation panel, controller and wire were exercised through host tests and a headless-browser smoke run against a synthetic GIF, not against a physical display.

Back up pages to a project before firmware updates. Preservation of the page storage region by the installed bootloader, UF2 and BLE OTA has not been verified on physical hardware. Legacy single-frame transmission and firmware update remain separate from page synchronization. Web Bluetooth requires a supported Chromium browser and HTTPS or localhost; the protocol does not authenticate nearby clients.
